# QA Checklist

Use this checklist before sending a web or design production asset for review.

## Layout Review

- [ ] The main message is visible without confusion.
- [ ] Visual hierarchy is clear.
- [ ] Spacing feels consistent.
- [ ] Elements are aligned intentionally.
- [ ] No content overlaps.
- [ ] The layout matches the approved direction or ticket requirements.

## Responsive Review

- [ ] Desktop layout has been reviewed.
- [ ] Tablet or mid-size layout has been reviewed.
- [ ] Mobile layout has been reviewed.
- [ ] Text remains readable on small screens.
- [ ] Buttons and links are easy to tap.
- [ ] No horizontal scrolling appears unless intended.

## Copy Review

- [ ] Headline is clear.
- [ ] Body copy supports the campaign goal.
- [ ] CTA text is direct and useful.
- [ ] Spelling and grammar have been checked.
- [ ] Tone matches the brief.
- [ ] No unsupported claims or fake statistics are included.

## Link and CTA Review

- [ ] CTA label is final or clearly marked as placeholder.
- [ ] Links point to the correct destination or are marked as demo links.
- [ ] Hover and focus states are visible.
- [ ] CTA placement is easy to find.

## Accessibility Basics

- [ ] HTML structure uses appropriate headings and landmarks.
- [ ] Text contrast is readable.
- [ ] Interactive elements can be reached by keyboard.
- [ ] Focus states are visible.
- [ ] Images have useful alt text if images are included.
- [ ] The page is understandable without relying only on color.

## SEO Basics

- [ ] Page title is clear if this is a full page.
- [ ] Meta description is included if this is a full page.
- [ ] Heading structure is logical.
- [ ] Copy includes relevant campaign language naturally.
- [ ] No hidden placeholder text remains.

## Asset Quality

- [ ] Images or generated visuals are high enough quality for the intended use.
- [ ] File names are clear.
- [ ] Files are not unnecessarily large.
- [ ] Visual assets do not include unintended logos, artifacts, or confidential references.
- [ ] Usage rights or source notes are documented when relevant.

## AI Output Review

- [ ] AI-generated text has been edited by a human.
- [ ] AI-generated claims have been checked.
- [ ] AI-generated visual prompts avoid real confidential client details.
- [ ] AI-assisted code has been reviewed for clarity and correctness.
- [ ] Any limitations or assumptions are documented.

## Final Approval

- [ ] Ticket acceptance criteria are complete.
- [ ] Known issues are fixed or documented.
- [ ] Stakeholder feedback has been addressed.
- [ ] Final files are organized.
- [ ] Delivery notes are included.
