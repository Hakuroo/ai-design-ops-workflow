# Workflow

This workflow shows how a creative request can move from a rough brief to a reviewed digital production output.

## Step 1: Receive the Brief

**Goal**  
Understand the request, business context, audience, timeline, and expected output.

**Actions**

- Read the full brief.
- Identify the campaign goal and primary audience.
- Note deliverables, formats, deadlines, and stakeholders.
- Flag missing information.

**Tools**

- Notion or Jira-style ticket board
- ChatGPT or Claude for brief summarization
- Figma if design references are provided

**Output**

- Short brief summary
- Initial list of questions
- Draft production scope

## Step 2: Clarify Requirements

**Goal**  
Remove ambiguity before design or implementation begins.

**Actions**

- Ask questions about audience, tone, content, assets, brand rules, and technical constraints.
- Confirm required formats and review rounds.
- Define what is in scope and out of scope.

**Tools**

- Notion/Jira-style comments
- ChatGPT or Claude for question drafting
- Team chat or project management tool

**Output**

- Confirmed requirements
- Known constraints
- Updated task notes

## Step 3: Convert the Brief Into Tickets

**Goal**  
Break the work into clear, trackable tasks.

**Actions**

- Create separate tickets for copy, visual exploration, implementation, QA, and delivery.
- Add acceptance criteria to each task.
- Assign owners and deadlines.
- Set status labels.

**Tools**

- Notion or Jira-style board
- Ticket template
- ChatGPT for acceptance criteria support

**Output**

- Production tickets
- Clear owners
- Reviewable task scope

## Step 4: Use AI for Research and Structure

**Goal**  
Use AI to support early organization and direction without replacing human judgment.

**Actions**

- Summarize the brief.
- Generate content structure options.
- Create a list of risks, assumptions, and open questions.
- Research category language at a high level without copying competitors.

**Tools**

- ChatGPT
- Claude
- Search and reference notes

**Output**

- Brief summary
- Content structure
- Risks and assumptions list
- Research notes for human review

## Step 5: Generate or Support Copy and Visual Exploration

**Goal**  
Create starting points for copy and visual direction that the team can edit and approve.

**Actions**

- Generate multiple headline and CTA options.
- Create visual exploration prompts.
- Review tone against the brief.
- Edit AI-generated content for clarity, brand fit, and accuracy.

**Tools**

- ChatGPT or Claude for copy support
- Midjourney, ComfyUI, or Krea.ai for visual exploration
- Figma for direction boards and review

**Output**

- Copy draft options
- Human-edited copy
- Visual prompt directions
- Selected direction notes

## Step 6: Implement Web-Ready Assets or Landing Sections

**Goal**  
Turn approved structure and content into usable front-end output.

**Actions**

- Build semantic HTML.
- Write responsive CSS.
- Use clear class names.
- Keep the implementation simple and easy to hand off.
- Use Cursor or AI support to debug layout issues when needed.

**Tools**

- HTML
- CSS
- JavaScript if interaction is required
- Cursor
- Browser developer tools

**Output**

- Web-ready section or asset
- Clean source files
- Notes for integration

## Step 7: QA Review

**Goal**  
Check that the output is clear, accurate, responsive, accessible at a basic level, and ready for review.

**Actions**

- Test desktop and mobile layouts.
- Review copy, links, CTA text, and visual hierarchy.
- Check asset quality and file weight.
- Confirm AI-generated outputs were reviewed by a human.
- Log issues and fixes.

**Tools**

- QA checklist
- Browser developer tools
- Figma
- ChatGPT or Claude for review support

**Output**

- Completed QA checklist
- Issue notes
- Fixed or documented problems

## Step 8: Final Delivery and Documentation

**Goal**  
Deliver the final work with enough context for another person to understand and reuse it.

**Actions**

- Package final files.
- Add delivery notes.
- Document assumptions, known limitations, and next steps.
- Move tickets to final status after approval.

**Tools**

- Notion/Jira-style board
- GitHub repository
- Figma handoff
- Delivery notes

**Output**

- Final source files
- Delivery summary
- Updated ticket statuses
- Clear next steps
